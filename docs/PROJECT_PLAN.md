## 2. Собствен алгоритъм: прогноза на остатъка и превишен бюджет

**Входни данни:** списък транзакции (сума, тип, дата, категория), бюджети (категория, лимит), днешна дата.
**Обработка (псевдокод):**
```
функция прогноза(транзакции, днес):
    d = ден от месеца;  rem = дни_в_месеца - d
    фиксирани   = разходи от категория „Жилище“
    променливи  = всички останали разходи
    дневни[i]   = сума на променливите за всеки от последните 45 дни
    ограничи всяка стойност до 4 × медиана(ненулевите дневни)   # еднократни големи покупки
    EMA = 0; за всеки ден: EMA = 0.12*ден + 0.88*EMA
    темп = 0.6*EMA + 0.4*(променливи_този_месец / d)
    фиксирани_очаквани = max(фиксирани_този_месец, фиксирани_миналия_месец)
    прогноза_разход = разходи_досега + (фиксирани_очаквани - фиксирани_този_месец) + темп*rem
    очакван_приход  = приходи от миналия месец, които още не са пристигнали
    върни {прогноза_разход, остатък = приходи + очакван_приход - прогноза_разход}

функция превишен_бюджет(похарчено, лимит, днес):
    проекция = похарчено / ден_от_месеца * дни_в_месеца
    ако похарчено > лимит        → "exceeded"
    иначе ако проекция > лимит   → "risk"      # + ден на изчерпване = ⌈лимит / (похарчено/ден)⌉
    иначе ако похарчено ≥ 85% лимит → "warning"
    иначе → "ok"
```
**Резултат:** прогнозиран разход и остатък в края на месеца; статус на всеки бюджет и ден на изчерпване; съвети на таблото.
Подробно описание, гранични случаи, сложност и ръчни примери: [ALGORITHM.md](ALGORITHM.md).

## 3. Технологии
- **HTML5, CSS3, JavaScript (ES2020)** — интерфейс и логика, без framework.
- **Supabase** (PostgreSQL, Auth, Row Level Security) — база данни, вход, права за достъп.
- **GitHub + GitHub Pages** — хранилище и публикуване.
- **Three.js** (допълнителна библиотека) — 3D визуализации (монета, 3D диаграма); нужна е, защото WebGL без библиотека е твърде сложен, а 3D анализът е нагледен за ученици. Не е критична за функционалността.
- **supabase-js** — официалният клиент за връзка с Supabase.
- **Chart.js** (препоръчана в заданието) — не ползваме; 2D диаграмите са собствен SVG код, за да имаме пълен контрол и по-малко зависимости. При нужда може да се замени.
- Външни API: **не използваме**.
